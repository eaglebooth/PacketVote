# Mechanism distinction (not a global novelty guarantee)

| Dimension | PacketVote | Nearest workspace distinction |
|---|---|---|
| Evidence | exact jointly accepted source clauses onchain | VoteGloss compares a submitted translation to the accepted source |
| Reasoning | counterfactual selective adoption for every code-enumerated bipartition | not token diff, policy-change classification or treasury intent compliance |
| Verification | independent full-source search for omitted-qualifier counterexamples | not format-only agreement or blind comparison of free-form summaries |
| Persistent state | canonical partition → plan-bound packet ballots → exact adopted source subset | not an evolving pairwise rule graph or append-only artifact applicability ledger |
| Consequence | changes indivisible voting units and enforces whole-packet adoption | no translated-edition gate, escrow payout or externally consumed treasury permit |

The mechanism enumerates possible separations first, then judges what changes when
one packet is omitted. Contract logic chooses a supported partition and constrains
subsequent voting/adoption to it. This is materially different from merely renaming
VoteGloss's source/translation fields or copying a general rule-precedence graph.
Authentication, expiry, strict parsing and no-replay invariants are reused principles.

This comparison is limited to inspected workspace documents and the declared
implementation. It cannot establish novelty against every submission in the queue.
